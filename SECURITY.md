# Segurança

## Relatar uma vulnerabilidade

Relatos privados de segurança são aceitos mesmo que este projeto pessoal não receba contribuições externas. Não há compromisso de prazo de resposta ou de correção.

Use o [formulário privado de vulnerabilidades do kvojps-monitor](https://github.com/kvojps/kvojps-monitor/security/advisories/new). É necessário entrar na sua conta do GitHub. Você também pode abrir o [repositório](https://github.com/kvojps/kvojps-monitor), acessar **Security → Advisories** e selecionar **Report a vulnerability**. O relato é compartilhado com os responsáveis autorizados pelo GitHub, sem abrir uma issue pública.

Inclua no relato:

- Uma descrição da falha, do impacto e do comportamento esperado.
- A versão do app ou revisão afetada e as versões relevantes do Ubuntu/GNOME.
- Passos mínimos para reprodução, usando dados fictícios ou sanitizados.

Não publique vulnerabilidades em issues, pull requests ou discussões públicas. Nunca publique credenciais, conteúdo de prompts ou respostas, mensagens de commits, conteúdo de cards ou outros dados pessoais. Mesmo no canal privado, remova tokens, senhas e chaves; substitua dados privados por exemplos mínimos antes de anexar logs, capturas ou arquivos. Confira também caminhos, nomes de projetos e sessões, contas, identificadores e endereços de rede.

Se o formulário privado não estiver disponível, não use um relato público como alternativa nem publique detalhes da falha ou dados sensíveis. Consulte novamente esta política para orientações atualizadas.

## Disponibilidade do canal

Em 02/11/2026, a API do GitHub confirmou a habilitação do canal privado neste repositório (`enabled: true`). A visibilidade do repositório não foi alterada nessa operação.

O canal habilitado e verificado é requisito para a abertura pública prevista para a v1. Na verificação acima, o repositório já estava público; o canal estava desabilitado e foi habilitado durante a execução do ticket 41.

Se for necessário reativá-lo, o mantenedor deve acessar **Settings → Advanced Security → Private vulnerability reporting → Enable** e verificar novamente a habilitação. Confira as [instruções oficiais do GitHub](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).
