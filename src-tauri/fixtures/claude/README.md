# Fixtures do Claude

- `statusline-payload.json`: JSON que o Claude Code entrega no stdin da status line, transcrito do exemplo da documentação oficial (https://code.claude.com/docs/en/statusline, lido em 2026-10-31). Não houve captura real: ela exigiria trocar a status line do usuário ou abrir uma sessão interativa só para isso. Os campos lidos pelo app (`rate_limits.five_hour` e `rate_limits.seven_day`, com `used_percentage` de 0 a 100 e `resets_at` em segundos Unix) seguem a tabela "Available data" da mesma página.
- `credentials.json`: as chaves reais de `~/.claude/.credentials.json` (Claude Code 2.1.316), com valores de exemplo; o app lê `subscriptionType` e, só com o opt-in `oauth/usage` ligado, `accessToken` e `expiresAt` em memória (nunca `refreshToken`).
- `settings.json`: forma do `~/.claude/settings.json` desta máquina, com uma status line e um hook instalados por outro app (Orca), encurtados.
- `oauth-usage.json`: resposta de `GET https://api.anthropic.com/api/oauth/usage` (opt-in), transcrita do teste real documentado em [`docs/research/limites-de-uso-ia.md`](../../../docs/research/limites-de-uso-ia.md), §3.3, plano Pro: `five_hour` 15% e `seven_day` 6% com `resets_at` em ISO 8601, buckets por modelo e produto (`seven_day_opus`, `seven_day_sonnet`, `seven_day_oauth_apps`, `seven_day_cowork`) todos `null`, e a lista `limits[]`. A pesquisa não registrou o conteúdo de `extra_usage` e `seven_day_breakdown`: aqui eles têm valores mínimos que só servem para conferir que campos desconhecidos são ignorados. Para regravar com a resposta atual desta máquina: `python3 -I src-tauri/fixtures/claude/capture.py` (lê o token só em memória e nunca o renova). Os testes derivam semanais por modelo não nulos, campos com codinome, 401, 5xx, 429 com `Retry-After`, falha de transporte e token vencido como variações controladas.
